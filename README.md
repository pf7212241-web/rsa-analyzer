# Учебная программа оценки стойкости ключей RSA

Библиотека на C17, графическое приложение Python/Tkinter и консольная версия для исследования открытых ключей `(n, e)`. Реализованы пробное деление, метод Ферма, метод Полларда p−1 с накопленным показателем `j!` и поиск общих множителей в наборе модулей. Ферма и Поллард p−1 выбраны для подробного разбора во второй главе курсовой.

Вычислительный диапазон — `uint64_t`, от 0 до 18446744073709551615. Отсутствие найденного разложения означает только результат конкретного запуска с заданными ограничениями. Программа не подтверждает криптографическую стойкость ключа. Малое значение открытой экспоненты само по себе не объявляется уязвимостью; атаки на сообщения и схемы дополнения не реализованы.

## Запуск из исходников

Проверенная среда — Windows x64, GCC из MinGW-w64, `mingw32-make` и Python 3.12 x64 с Tkinter. Компилятор, Make и Python должны быть доступны в `PATH`.

Откройте PowerShell в корне проекта, где находится `Makefile`, и выполните:

```powershell
mingw32-make all
python gui/main.py
```

Для быстрой проверки откройте вкладку «Инструкция», загрузите пример Ферма и нажмите «Выполнить анализ». В результате появится разложение `10403 = 101 × 103`.

## Работа в графическом приложении

Во вкладке **«Анализ»** введите n и e либо выберите файл. **«Настройки»** позволяют выбрать методы и лимиты. **«Инструкция»** содержит пошаговое руководство и наглядный разбор `10403 = 101 × 103`. Кнопки примеров подставляют данные и включают сравнение; анализ запускается отдельной кнопкой.

Кнопка **«Остановить»** отменяет текущий запрос. Предыдущий завершённый результат остаётся доступен. **«Сохранить отчёт…»** сохраняет именно завершённый запуск, включая его настройки и контрольные значения. После изменения полей прежний результат помечается соответствующим пояснением. Для сохранения выбирайте новое имя: существующие файлы не перезаписываются.

Графическая оболочка получает результаты через `ctypes` из `rsa_core.dll`. Математические алгоритмы не переписаны на Python. Вычисления выполняются в отдельном процессе, поэтому не блокируют окно. Все расчёты локальные, сетевых запросов приложение не выполняет.

## Упаковка приложения для Windows

Проверенная поставка собрана с Python 3.12.14 и PyInstaller 6.22.3 на Windows 11 x64. Для самостоятельной упаковки установите PyInstaller и выполните:

```powershell
python -m pip install --target build/packaging-deps PyInstaller==6.22.3
.\build_gui.ps1 -Python "C:\путь\к\python.exe"
```

Укажите реальный путь к интерпретатору. После упаковки откройте `release/RSA-Analyzer/RSA-Analyzer.exe`. Папка `_internal` должна лежать рядом с EXE. Для переноса готового приложения скопируйте папку `RSA-Analyzer` целиком. Скрипт обновляет только выходной каталог `release/RSA-Analyzer`; пользовательские отчёты храните вне каталога поставки. Пиктограммы включены в исходники; Pillow нужен только для их повторной генерации, приложению он не требуется.

## Запуск консольной версии

Консольная программа: `build/rsa_analyzer.exe`. Её можно открыть двойным щелчком: появится русскоязычное меню. Для файлового ввода в меню указывайте путь без кавычек; пустое имя отчёта оставляет вывод только на экране.

Команды PowerShell из каталога `rsa_analyzer`:

```powershell
.\build\rsa_analyzer.exe
.\build\rsa_analyzer.exe --key "10403 7" --compare
.\build\rsa_analyzer.exe --key "261883 3" --methods 4 --pollard-bound 20
.\build\rsa_analyzer.exe --file .\examples\keys.txt --compare --output .\build\report.txt
.\build\rsa_analyzer.exe --help
```

`10403 = 101 × 103` — пример близких множителей для Ферма. `261883 = 257 × 1019` — пример для Полларда p−1: число `257 − 1` содержит только степень двойки. Настройки можно менять через пункт 3 меню или аргументы запуска.

Файл отчёта создаётся только под новым именем. Если такой файл уже существует, программа сообщит об ошибке; для следующего запуска выберите другое имя. Вывод одновременно остаётся на экране.

## Входные данные

Файл в UTF-8, допускается BOM. Каждая непустая строка содержит **два или пять** полей:

```text
# n e
10403 7
# n e p q d
3233 17 61 53 2753
# Из контрольных параметров известен только q
3233 17 - 53 -
# Число за пределами uint64_t: информационный режим
18446744073709551616 65537
```

Поля разделяются пробельными символами. Комментарий `#` допустим в начале строки или после пробельного символа. Дефис обозначает отсутствие контрольного параметра. Числа записываются десятичными цифрами без знака, допускаются ведущие нули.

- До 256 записей в одном файле; ошибочная строка также считается записью. Комментарии и пустые строки не считаются.
- До 1024 цифр в каждом из `n` и `e`, включая ведущие нули; до 5199 байт в строке без завершающего перевода строки.
- Контрольные `p`, `q`, `d`, если указаны, должны помещаться в `uint64_t`.
- При вычислительном анализе требуется `n > 1`, `1 < e < n`. Простой, чётный или квадратный модуль может быть принят для диагностики, но не признаётся соответствующим принятой модели RSA.
- Если `n` или `e` не помещается в `uint64_t`, проверяется десятичная запись и положительность, вычисляется разрядность. Факторизация, поиск общих множителей и проверки соотношений RSA для такой записи не выполняются. Разрядность получается последовательным делением десятичной строки на 2; универсальная длинная арифметика не используется.
- Ошибка отдельной строки включается в отчёт, остальные записи обрабатываются. Ошибка чтения файла, нехватка памяти или превышение 256 записей прекращает обработку запроса.

Файлы `examples/keys.txt` и `examples/invalid.txt` содержат диагностические примеры. Это набор для проверки корректности, а не результаты эксперимента по производительности.

## Настройки и режимы

| Параметр запуска | По умолчанию | Назначение |
|---|---:|---|
| `--methods` | 7 | Сумма флагов: 1 — пробное деление, 2 — Ферма, 4 — Поллард; 0 отключает три метода, сохраняя диагностику и поиск общих множителей |
| `--trial-bound` | 100000 | Максимальный проверяемый делитель D, не меньше 2 |
| `--pollard-bound` | 10000 | Последний показатель j в цепочке `x ← x^j mod n`, B ≥ 2 |
| `--base` | 2 | Основание Полларда, не меньше 2; для нечётного n требуется основание < n |
| `--iterations` | 100000 | Положительный лимит итераций **каждого** метода |
| `--seconds` | 1.0 | Положительный конечный лимит секунд **каждого** метода |
| `--compare` | Выключен | Независимый запуск всех выбранных методов на исходном n |

В обычном режиме уже известное разложение позволяет пропустить дальнейшие методы. Источником могут быть контрольные параметры, общий множитель или предыдущий метод. В режиме сравнения эти сведения не используются как подсказка другим методам. Поиск общих множителей проводится до индивидуальных запусков.

Все настройки проверяются, даже если соответствующий метод отключён. Библиотека позволяет задавать разные лимиты трём методам; оболочка устанавливает одинаковые лимиты для удобства.

Единицы счётчика итераций:

- Пробное деление: один проверенный нечётный делитель, начиная с 3. Проверка чётности — подготовительная операция.
- Ферма: одна проверка, является ли `a² − n` квадратом, включая начальное значение a.
- Поллард p−1: одно возведение `x^j mod n` и последующий НОД, начиная с j = 2. Предварительный НОД основания и модуля в счётчик не входит.

В Windows время измеряется `QueryPerformanceCounter`. Лимит проверяется перед очередной итерацией; текущая операция не прерывается. Это не жёсткое ограничение общего времени запроса: ввод, диагностика, парные НОД и формирование отчёта находятся вне лимитов методов. Числа итераций разных методов имеют разный смысл и напрямую не равнозначны.

## Интерпретация результатов

| Статус метода | Значение |
|---|---|
| `FOUND` | Найдены u и v; проверены нетривиальность, делимость и равенство v = n / u |
| `SEARCH_COMPLETED` | Поиск завершён: причина уточняет полный перебор или достижение D/B |
| `LIMIT_REACHED` | Остановка по времени или числу итераций |
| `DEGENERATE` | В методе Полларда получен НОД, равный n |
| `INVALID_INPUT` | Некорректные аргументы или основание Полларда |
| `UNSUPPORTED_RANGE` | Дальнейшее вычисление не представимо либо недоступен таймер; причина указывается отдельно |
| `NOT_RUN` | Метод отключён или разложение уже известно в обычном режиме |

Подтверждённое разложение не обязательно состоит из простых множителей. Соответствие модели проверяется отдельно: два различных нечётных простых p и q и `gcd(e, (p−1)(q−1)) = 1`. При отсутствии достаточных данных результат проверки модели остаётся неизвестным. Для контрольного d используется учебное условие `e·d ≡ 1 mod φ(n)`, а не более общее условие через функцию Кармайкла. Поэтому некоторые d, допустимые при определении через λ(n), здесь не будут подтверждены.

Если указан только p или q, второй множитель восстанавливается делением. Если указан только d, его проверка откладывается до нахождения множителей. Неверный контрольный параметр отмечается отдельно от результата анализа самого открытого ключа. Дубликаты модулей и делимость одного модуля на другой различаются в отчёте: совпадение n не считается найденным нетривиальным разложением.

Коды завершения командного запуска: `0` — запрос обработан; `2` — ошибка входа, параметров, чтения или памяти; `3` — ошибка вывода/сохранения. Неподтверждённая модель, неверные контрольные параметры и достижение лимита являются результатами анализа, а не ошибкой запуска. Интерактивное меню сообщает ошибки и продолжает работу; при обычном выходе возвращает 0.

## Сборка и устройство

Проверенная среда: Windows, GCC/MinGW 16.1.0, `mingw32-make`. Из каталога проекта:

```powershell
mingw32-make
mingw32-make test build/math_probe.exe
python tests/test_integration.py
```

Компилятор и Make должны быть доступны в PATH. Консольная версия запускается без Python. Для тестов и запуска графической оболочки из исходников нужен Python с Tkinter. Флаги сборки: C17, `-Wall -Wextra -Wpedantic -Werror`. Поддержка POSIX предусмотрена в исходниках, но в этой работе проверялась сборка Windows.

```text
include/      публичные типы и объявления библиотеки
src/          math_utils, timing, factorization, analysis
app/          main и input_output: меню, параметры, файлы, отчёт
              gui_bridge: адаптер DLL для графической оболочки
gui/          Tkinter, ctypes, управление рабочим процессом
assets/       пиктограмма приложения
tests/        тесты C, арифметический адаптер, проверки Python
examples/     входные наборы
docs/         контракты, соответствие главе, результаты проверки
build/        объектные файлы, статическая библиотека librsa.a, программа
Makefile      правила сборки
build_gui.ps1 упаковка Windows-приложения
release/      готовая графическая поставка
```

Вычислительное ядро не читает stdin и не печатает сообщения. Консольная оболочка включает заголовки и связывается с `librsa.a`; графическая обращается к DLL. Все результаты передаются структурами; изменяемых глобальных переменных в ядре нет. Строковые значения больших чисел обрабатываются модулем ввода и не передаются в вычислительные алгоритмы.

Безопасное модульное умножение использует удвоение и сложение с предварительным вычитанием модуля. В методе Ферма хранится разность квадратов и обновляется по формуле `z ← z + 2a + 1`; переполнение проверяется до операции. Внешние криптографические библиотеки, тип `__int128` и универсальная длинная арифметика не используются.

Проверка простоты — Миллер — Рабин с основаниями 2, 325, 9375, 28178, 450775, 9780504, 1795265022 для диапазона n < 2⁶⁴. Источник набора: [Deterministic variants of the Miller–Rabin primality test, результат Jim Sinclair от 20.04.2011](https://miller-rabin.appspot.com/). Для больших строковых чисел этот тест не вызывается.

Контракты функций и переход от первой главы описаны в `docs/architecture.md`; фактические проверки — в `docs/verification.md`.

Устройство GUI и новые проверки описаны в `docs/gui-implementation.md`. Для повторения тестов интерфейса после сборки DLL:

```powershell
python tests/test_gui_bridge.py
python tests/test_gui_window.py
```
