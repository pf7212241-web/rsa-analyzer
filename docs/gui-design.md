# Графический интерфейс программы оценки RSA

Дата: 10.11.2026. Статус: согласовано пользователем и реализовано. Фактическое устройство и проверки описаны в gui-implementation.md.

## Задача

Преподаватель требует графический интерфейс вместо одной консольной оболочки. Пользователь просит минималистичное оформление, принадлежность к тематике RSA, вкладку с инструкцией и наглядный пример. Вычислительное ядро на C, согласованные методы и ограничения сохраняются.

## Подход

Рассмотрены два варианта: Python с Tkinter/ttk и Python с PySide6. Tkinter/ttk выбран как предложение исполнителя: имеющегося набора элементов достаточно для формы, вкладок, таблицы и инструкции; модули tkinter и ctypes доступны в рабочем Python. PySide6 потребовал бы дополнительную GUI-зависимость без необходимой для текущей задачи функции.

Существующая статическая библиотека дополнительно собирается в DLL. Python вызывает C через ctypes. Запуск консольной программы и разбор её русскоязычного вывода не используются как основной протокол обмена: интерфейс получает структурированные результаты. Консольная версия остаётся доступной для воспроизводимых тестов.

Документация: [Tkinter](https://docs.python.org/3/library/tkinter.html), [ctypes](https://docs.python.org/3/library/ctypes.html).

## Окно и оформление

Название: «RSA — оценка ключей». Подзаголовок: «Учебный анализ стойкости». Принадлежность подчёркивается небольшой графической записью n = p × q; сведения об авторе «Филиппов Павел» размещаются в инструкции. Название вуза и логотип не выдумываются.

Светлый фон #F4F6F9, белая рабочая область #FFFFFF, основной текст #192B40, вторичный текст #56677C, синий акцент #2459A6, границы #D7DEE8. Segoe UI для интерфейса, Consolas для числового примера. Цвет статуса всегда сопровождается текстом. Без декоративных анимаций и множества карточек.

Окно изменяемого размера, ориентир 1100 × 760; содержимое доступно при 900 × 650 через прокрутку. Все подписи на русском. Поля и кнопки доступны с клавиатуры, фокус виден. Длинные значения не обрезаются без возможности прокрутки или копирования.

Три вкладки: «Анализ», «Настройки», «Инструкция».

```text
RSA — оценка ключей                         n = p × q
Учебный анализ стойкости

[ Анализ ]  [ Настройки ]  [ Инструкция ]

Один ключ / Набор из файла       [Загрузить пример]
n: [........................]   e: [..............]
Контрольные параметры (необязательно): p, q, d
[Выбрать файл…]  выбранный путь / число записей

[Выполнить анализ] [Остановить]     Состояние работы

Результаты набора / выбранный ключ
Метод       Результат       Итерации       Время
Ферма       ...             ...            ...
Поллард p−1 ...             ...            ...

Пояснение результата, множители, общие делители
[Сохранить отчёт…]
```

Эскиз показывает состав, а не окончательные размеры элементов. В режиме одного ключа отображаются его поля; в файловом режиме — выбор файла и список результатов. Неактуальные элементы скрываются или отключаются.

## Анализ

Пользователь вводит n и e в отдельных полях либо выбирает файл через стандартное диалоговое окно. Контрольные p, q, d необязательны; пустое поле означает отсутствие значения. Дополнительная группа с ними сворачивается, чтобы не перегружать первый запуск.

Формат файлов и ограничения существующей программы сохраняются: UTF-8, записи n e или n e p q d, до 256 записей, до 1024 цифр в n и e. Ошибочные строки остаются видимыми в результатах; исправные обрабатываются. Пользователь выбирает строку набора и видит результаты методов, контрольных проверок и связанных модулей с номерами исходных строк.

Для больших значений показываются разрядность и явное пояснение информационного режима. Метки «ключ надёжен» или процент стойкости не вводятся. Статусы различают найденное разложение, остановку по лимиту, вырожденный результат, ошибку параметров и отсутствие выполненной проверки. Несоответствие учебной модели отображается отдельно от статуса метода.

Анализ выполняется вне потока интерфейса. Во время работы виден индикатор без вымышленного процента, нельзя запустить второй запрос. Кнопка «Остановить» прекращает текущий запрос через завершение отдельного рабочего процесса; неполный результат не объявляется полным отчётом. Ранее завершённый отчёт, если есть, остаётся доступен с указанием, что относится к предыдущему запуску. Закрытие окна завершает рабочий процесс.

Сохранение отчёта — через выбор пути. Отчёт содержит исходные данные и настройки именно завершённого запуска, результаты и ограничения интерпретации. Существующий файл не перезаписывается молча; используется действующая политика создания нового файла. После изменения входа прежний результат явно обозначается как результат предыдущего запуска.

## Настройки

Флажки трёх методов, переключатель обычного режима/независимого сравнения, D, B, основание Полларда, время и итерации каждого метода (в первой версии одно значение лимита применяется ко всем трём, как в консольной оболочке). Сохраняются действующие значения по умолчанию. Есть кнопка «Восстановить значения по умолчанию» и краткие пояснения рядом с полями. Ошибка указывается около соответствующего поля и блокирует запуск.

## Инструкция и пример

Инструкция встроена в приложение и доступна без интернета. Разделы: назначение и ограничения; ввод одного ключа; формат файла; настройка и сравнение методов; чтение результата; сохранение отчёта.

Основной пример: n = 10403, e = 7. Иллюстрация показывает 10403 → 101 × 103. Для Ферма: a = 102, a² − n = 1 = 1², поэтому множители равны 102 − 1 и 102 + 1. Пояснение отделяет учебный разбор от фактических измерений времени.

Кнопка «Подставить пример» переводит на вкладку «Анализ», заполняет поля и устанавливает известные настройки сравнения. Анализ запускается отдельной кнопкой. При замене уже введённых данных пользователь получает подтверждение. Дополнительный пример для Полларда: n = 261883, e = 3, множители 257 и 1019; для общего множителя используется файл из существующего examples.

## Связь Python и C

Алгоритмы и диагностические проверки остаются в C. Оболочка управляет виджетами, рабочим процессом и отображением. Для повторного использования чтения и проверки записей допускается небольшой C-адаптер, принимающий текст либо путь; FILE* через границу Python/C не передаётся.

Сигнатуры ctypes задаются явно, диапазон проверяется до преобразования Python int в uint64_t. Структуры, размеры полей и выравнивание сверяются с C. Память, выделенную библиотекой, освобождает функция этой же библиотеки. DLL загружается из каталога поставки по полному пути. Конкретные имена адаптера и внутренних классов оставлены исполнителю.

## Поставка и проверка

Целевая платформа первой версии — Windows x64. Результат: исходники Python и C, инструкция сборки, запускаемая графическая версия. Для передачи преподавателю предусматривается отдельная папка приложения с exe и зависимостями, без требования устанавливать Python на его компьютере. Средства упаковки пока не установлены; подготовка и проверка такой сборки входят в реализацию, успешная упаковка заранее не утверждается.

Проверить: прежние тесты C; совпадение результатов DLL и консольной версии; граничные значения; одиночный и файловый ввод; кириллицу; настройки; пример из инструкции; сохранение; остановку и повторный запуск; закрытие во время анализа; размеры окна и читаемость; запуск поставки без обращения к рабочему Python. Число итераций сравнивается при одинаковых условиях без срабатывания времени, фактическое время может различаться.

В документации курсовой потребуется заменить описание исключительно консольной оболочки на графическую, статическую компоновку оболочки — на связь Python/ctypes/DLL. Разделы 2.4.1 и 2.4.2 будут описывать действующие экраны и передачу данных. Изменения Word и написание глав выполняются после готовности интерфейса отдельным этапом.
