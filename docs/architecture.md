# Контракты и соответствие проекту

## Граница библиотеки

`rsa_types.h` задаёт общие типы. `math_utils` реализует целочисленную арифметику; `timing` — измерение времени; `factorization` — методы и настройки; `analysis` — проверку модели, контрольных данных, одного ключа и набора. Ввод, большие десятичные строки и форматирование отчёта находятся в `app/input_output.c`. Меню и аргументы запуска находятся в `app/main.c`.

| Функция | Вход и результат |
|---|---|
| `gcd64` | Любые два uint64_t; НОД, включая gcd(0, 0) = 0 |
| `add_mod64`, `mul_mod64`, `pow_mod64` | Модуль строго положителен; результат меньше модуля; нарушение этого предусловия недопустимо |
| `integer_sqrt64` | Любой uint64_t; нижняя целая граница квадратного корня |
| `is_prime64` | Любой uint64_t; проверка простоты в данном диапазоне |
| `bit_length64` | Любой uint64_t; для нуля возвращает 0 |
| `default_settings` | Возвращает полностью инициализированные настройки |
| `settings_valid` | Проверяет общие границы и лимиты; NULL даёт false |
| `trial_division`, `fermat_factor`, `pollard_p_minus_one` | n > 1 и настройки; возвращают структуру результата, не выделяют память; плохие аргументы отражаются в статусе |
| `analyze_key` | Ключ и настройки, ref либо NULL, ненулевой out; при OK заполняет весь отчёт, динамической памятью он не владеет |
| `check_common_factors` | До 256 ключей и заранее инициализированные out->reports с теми же ключами и count; out->pairs должен быть NULL; создаёт массив связанных пар и дополняет отчёты |
| `analyze_batch` | До 256 ключей, настройки, refs либо NULL; массив refs, если есть, содержит count элементов. out должен быть нулевой структурой либо ранее освобождённым отчётом |
| `free_batch_report` | Освобождает reports и pairs, обнуляет структуру; повторный вызов и NULL допустимы |

Входные указатели относятся к действительным объектам заявленного размера. Если проверка аргументов публичной функции анализа не пройдена, выходной отчёт не заменяется. При ошибке выделения памяти внутри `analyze_batch` уже созданные массивы освобождаются. При успешном вызове их владельцем становится вызывающая сторона. `check_common_factors` используется после инициализации отчётов внутри `analyze_batch`; обычному клиенту достаточно вызывать `analyze_batch`.

Пример жизненного цикла:

```c
AnalysisSettings settings = default_settings();
RsaPublicKey keys[] = {{10403, 7}, {3233, 17}};
BatchReport report = {0};
AnalysisStatus status = analyze_batch(keys, 2, &settings, NULL, &report);
/* При status == OK приложение читает report.reports и report.pairs. */
free_batch_report(&report);
```

Пустой набор допустим. Для него можно передать keys = NULL, count = 0; при корректных настройках результат OK. Контрольные параметры читаются только при установленном has_p, has_q или has_d. Найденные u, v читаются при has_factors, а u, v отдельного метода — при FOUND.

## Путь данных в оболочке

`process_request` получает выбранный источник, настройки и путь отчёта. При файловом вводе `read_input` читает строки и вызывает `validate_input`; при вводе одного ключа `validate_input` вызывается непосредственно. Затем `describe_large_keys` вычисляет разрядность больших значений. `analyze_input` формирует компактный массив вычислительных ключей и вызывает `analyze_batch`. `write_report` объединяет результаты с исходными номерами строк. `cleanup` освобождает входные записи и вызывает `free_batch_report`.

Объект `AppData` перед первым использованием обнуляется. `read_input` принимает открытый FILE и пустой AppData; поток остаётся собственностью вызывающей стороны. `validate_input` изменяет переданную строку, вставляя нулевые терминаторы; запись перед вызовом должна быть обнулена. `read_line` принимает действительный поток, буфер ёмкостью не менее 1 байта; -1 означает слишком длинную строку или нулевой байт. `parse_positive_seconds` принимает ненулевые указатели на строку и выходной double. Оболочка соблюдает эти предусловия.

Для укрупнённой схемы использовать функции:

| Блок | Функция | Данные на выходе |
|---|---|---|
| Чтение файла | `read_input` | AppData с разобранными записями и ошибками |
| Проверка отдельной записи | `validate_input` | InputRecord: вычислительная, информационная или ошибочная запись |
| Информация о больших числах | `describe_large_keys` | Разрядности n и e |
| Анализ вычислительных записей | `analyze_input` | BatchReport и соответствие записям файла |
| Анализ набора внутри библиотеки | `analyze_batch` | Массив отчётов и общих множителей |
| Формирование отчёта | `write_report` | Текст в переданный FILE |
| Освобождение ресурсов | `cleanup` | Освобождённые массивы |

В схеме не нужно повторно вызывать `validate_input` после `read_input`: проверка уже входит в чтение. Стратегические ветвления — выбор источника и успех ввода/анализа. Внутренние циклы факторизации показываются лишь в подробном объяснении алгоритмов. Подготовка настроек в меню выполняется `configure`, при командном запуске — `run_application` с вызовами `apply_option`.

## Уточнения для текста первой и второй глав

Реализация сохраняет согласованные алгоритмы и режимы. Перед окончательной сборкой курсовой необходимо перенести следующие уточнения в таблицы, прототипы и изображения первой главы. В этом этапе Word-документ не изменялся.

| Проектное имя первой главы | Имя в коде |
|---|---|
| `trialDivision` | `trial_division` |
| `fermatFactor` | `fermat_factor` |
| `pollardPMinusOne` | `pollard_p_minus_one` |
| `analyzeKey` | `analyze_key` |
| `checkCommonFactors` | `check_common_factors` |
| `analyzeBatch` | `analyze_batch` |
| `freeBatchReport` | `free_batch_report` |
| `readInput` | `read_input` |
| `validateInput` | `validate_input` |
| `describeLargeKeys` | `describe_large_keys` |
| `writeReport` | `write_report` |
| `cleanup` | `cleanup` |

В `AnalysisReport` вместо обобщённого `warning_flags` используются явные поля `has_factors`, `prime_pair`, `u`, `v`, `model_status`, `control_status`. Так можно отдельно описать факт разложения, состав множителей, соответствие модели и результат контрольных данных. `AnalysisSettings` содержит `pollard_base`, `selected[3]`, `limits[3]`, `compare_mode`; точный состав брать из `include/rsa_types.h`.

`read_input` читает ключи из файла, настройки получает оболочка отдельно. `write_report` пишет в уже открытый поток; открытие файла, запрет перезаписи и закрытие выполняет `process_request`. `analyze_input` — дополнительная функция оболочки, сохраняющая соответствие между смешанным набором записей и компактным массивом результатов библиотеки. Эти уточнения нужно учесть в пояснении схемы, сохранив её укрупнённый уровень.

Для разделов 2.3.2 и 2.3.3 основной материал находится в `src/factorization.c`: `fermat_factor` и `pollard_p_minus_one`. Их вспомогательные вычисления — в `src/math_utils.c`. Снимки кода следует делать после окончательного согласования листинга; результаты быстродействия относятся к третьей главе.
