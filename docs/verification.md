# Протокол проверки реализации

Среда: Windows x64, GCC/MinGW 16.1.0. Проверка выполнена 09–10.11.2026. Протокол относится к корректности реализации; сравнительный эксперимент для третьей главы ещё не проводился.

Дополнение 10.11.2026: графическая оболочка реализована и проверена. Прежние проверки ниже повторены успешно; дополнительно прошли 6 тестов DLL/рабочего процесса и 4 теста окна. Подробности — в `gui-implementation.md`.

## Выполненные проверки

1. Сборка C17 с `-O2 -Wall -Wextra -Wpedantic -Werror`: успешно.
2. `tests/test_core.c`: **22 255 проверок**, ошибок нет. Проверены арифметические границы, простота и целые корни для малых значений, методы на диапазоне 2–499, корректность найденных делителей, близкие множители у верхней границы uint64_t, лимиты, вырожденный результат Полларда, частичные и неверные контрольные данные, независимость методов, общий множитель, дубликаты и освобождение отчёта.
3. `tests/test_integration.py` и `tests/math_probe.c`: **6 015 независимых арифметических сравнений**, ошибок нет. На 1203 наборах сравниваются НОД, модульное произведение, модульная степень, целый квадратный корень и разрядность с Python `math.gcd`, целыми числами произвольной точности, `pow`, `math.isqrt`, `bit_length`. Псевдослучайная последовательность фиксирована для воспроизводимости.
4. Пользовательские сценарии: командный запуск, меню, настройки, 65-битные и 1024-значные числа, ведущие нули, ошибочные поля и параметры, BOM, кириллица в путях, смешанные файлы, точные номера строк в общих множителях, совпадение экранного и файлового отчёта, запрет перезаписи входа, длинная строка, нулевой байт, 257 записей и пустой файл. Все проверки прошли.
5. GCC `-fanalyzer`: модули `analysis.c`, `input_output.c`, `main.c` проверены без диагностик. Команды используют `-std=c17 -Wall -Wextra -Wpedantic -Werror -Iinclude -Iapp -fanalyzer -c`.

## Ограничения проверки

Запуск AddressSanitizer/UndefinedBehaviorSanitizer недоступен в установленной сборке MinGW: линковщик не находит `-lasan` и `-lubsan`. Поэтому динамическая проверка этими средствами не выполнена. Успех функциональных тестов и статического анализа не является доказательством отсутствия всех ошибок памяти.

Проверялась Windows-сборка. Ветка POSIX не запускалась. Временные лимиты проверялись как условия остановки, а не как гарантия точного времени. Числа итераций разных алгоритмов измеряют разные операции; сравнение производительности требует отдельной методики и повторных измерений.

## Повторение

Из каталога проекта:

```powershell
mingw32-make
mingw32-make test build/math_probe.exe
python tests/test_integration.py
```

Тест Python использует только стандартную библиотеку. Временные файлы создаются в build и удаляются после проверки. Полный успешный вывод последних двух команд содержит `22255`, `Independent arithmetic checks: 6015` и сообщение об успешной проверке пользовательских сценариев.
