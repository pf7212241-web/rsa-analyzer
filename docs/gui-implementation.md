# Реализация графической оболочки

Согласованный проект реализован 10.11.2026. Основная поставка — Windows x64, Python 3.12.14/Tkinter/ttk, PyInstaller 6.22.3. Алгоритмы выполняются в исходном ядре C17.

## Модули и путь данных

- `gui/main.py`: запуск окна либо служебного рабочего процесса по аргументу `--worker`. Настройка DPI применяется только к процессу приложения.
- `gui/window.py`: вкладки, поля, настройки, таблицы, инструкция и стандартные диалоги. `Application.start` проверяет ввод и создаёт запрос; `poll` принимает завершённый результат; `show_record` показывает выбранную строку; `save` сохраняет неизменяемый снимок завершённого запуска.
- `gui/jobs.py`: `AnalysisJob` запускает отдельный скрытый процесс и опрашивает его без блокировки Tk. Запрос и результат хранятся в уникальном временном каталоге. Результат публикуется переименованием готового JSON; промежуточный файл не читается. При остановке/закрытии процесс завершается, каталог освобождается.
- `gui/bridge.py`: явные сигнатуры ctypes и структуры C. До обращения к данным проверяются размеры всех десяти структур и смещения всех полей через `gui_layout`. Путь DLL абсолютный, внутри поставки. Числовые настройки проверяются до преобразования в uint64_t.
- `app/gui_bridge.c`: `gui_load` принимает текст ключа либо путь и использует действующий разбор C; `gui_write_report` открывает и закрывает файл внутри той же DLL; `gui_layout` сообщает ABI компилятора. FILE* между Python и C не передаётся.

В рабочем процессе выполняется последовательность: `gui_load` → `describe_large_keys` → `analyze_input` → копирование структур в Python → `gui_write_report` → `cleanup`. `cleanup` вызывается в finally, в том числе после ошибок. Контрольные введённые p, q, d добавляются в текст отчёта для воспроизводимости. Отчёт C не используется как протокол получения числовых результатов.

Большие числа остаются строками в модуле ввода C. Для них не вводятся новые вычислительные проверки. Python int используется при проверке диапазона полей, но не заменяет согласованные 64-битные алгоритмы.

В интерфейсе доступны три метода, обычный режим и независимое сравнение, границы D и B, основание Полларда, общий для методов лимит итераций и времени. Контрольные поля можно раскрывать; скрытие не удаляет введённые значения. Примеры из инструкции подставляются с подтверждением замены непустого ввода. Сохранение создаёт новый файл, а не перезаписывает существующий.

## Проверки

Автоматические сценарии:

- `test_gui_bridge.py`: 6 тестов — сверка ABI, сравнение с консолью без учёта времени, три метода и предельные значения, большие числа, контрольные данные, смешанные файлы и кириллица, ограничения ввода, рабочий процесс и отмена с очисткой файлов.
- `test_gui_window.py`: 4 теста — пример и результат, отметка старого результата после редактирования, сохранение без перезаписи, ошибки полей/настроек, большие числа, подтверждение замены, остановка, закрытие во время расчёта, файловый набор с ошибкой и общим множителем, пустой файл.
- Сохранены прежние проверки C и независимой арифметики Python.

Дополнительно проверяется фактическая поставка exe: рабочий режим с очищенными PYTHONPATH/PYTHONHOME/TCL_LIBRARY/TK_LIBRARY и PATH, содержащим только системный каталог Windows; окно, подстановка примера и запуск из интерфейса. Это проверка автономности на текущем компьютере, а не испытание на всех версиях Windows или на компьютере преподавателя.

Динамические ASan/UBSan по-прежнему недоступны в установленной сборке MinGW. Полноценные измерения эффективности для третьей главы не выполнялись.

## Сборка и документация курсовой

`mingw32-make all` создаёт консольную программу, статическую библиотеку и `rsa_core.dll`. `build_gui.ps1` собирает папку `release/RSA-Analyzer` с exe и зависимостями. В каталоге `_internal` находятся DLL ядра, Python, Tcl/Tk, примеры и пиктограмма. Исходный код поставляется отдельно.

Для второй главы нужно описать динамическую связь Python/ctypes/DLL вместо исключительно статической компоновки оболочки, а в 2.4 — действующие вкладки и жизненный цикл запроса. Укрупнённую схему обработки строить по функциям C: gui_load, describe_large_keys, analyze_input, gui_write_report, cleanup; каждый предопределённый процесс соответствует существующей функции. Обработчики событий Python описывать отдельно, с явно обозначенной границей языков, не выдавая их за функции C.

Word-документ в этом этапе не изменялся; перечень изменений для синхронизации первой главы сохраняется в `architecture.md` и дополняется данным описанием.
